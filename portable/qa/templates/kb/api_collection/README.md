# API — коллекция запросов

Коллекция запросов к API проекта. Источник схем — снапшот API-спеки в `wiki/raw/`
(пути и даты снапшотов — раздел 1 `../project-passport.md`).

**Этот README описывает Bruno — инструмент по умолчанию.** Выбор инструмента и правила
ведения коллекции живут в паспорте в шапке [`CLAUDE.md`](CLAUDE.md); если на проекте
Postman или что-то ещё, перепишите разделы ниже и удалите `bruno.json`.

## Как открыть (профиль Bruno)

1. Установить [Bruno](https://www.usebruno.com/) (бесплатно, desktop-приложение).
2. **Open Collection** → выбрать папку `api_collection`.
3. Выбрать окружение: **Environment** → Local или Dev.
4. При необходимости заполнить переменные окружения и вручную сохранить (иконка дискеты).

## Структура

```
api_collection/
├── bruno.json              # метаданные коллекции (обязателен для открытия)
├── environments/           # local.bru (localhost), dev.bru (тестовый стенд)
└── <Раздел>/               # добавляется по мере перехода к следующему флоу
```

Коллекция пуста — разделы заводятся по мере тестирования флоу, каждый со своим README
или комментарием в `name` запроса, если нужны пояснения по порядку прогона.

## Как работает авторизация

1. Выполнить логин (или регистрацию/сброс пароля — то, что возвращает токен) — скрипт
   сохраняет `accessToken`, `refreshToken` и `userId` в переменные коллекции.
2. Все защищённые запросы берут токен через `auth: bearer { token: {{accessToken}} }`.

## С каким аккаунтом работаем

Опишите здесь принятую на проекте схему: фиксированные тестовые учётки, или генерация
нового адреса на каждый прогон регистрации (через `script:pre-request` и `bru.setVar`),
или и то, и то через переключатель в окружении.

## Роли

Значения `role`/аналогичного enum — ровно из спеки API. Термины бизнес-документов, если
отличаются от кода, в API не используются (см. `glossary` в вики).
