# Гид по AI-скиллам шаблона: как тестировщику работать с агентом

Шаблон поставляется с набором скиллов Claude Code — упакованных процедур,
по которым агент пишет тесты в конвенциях фреймворка. Ты говоришь ЧТО
покрыть, агент знает КАК: срез спеки, матрица до кода, эталоны, verify.
Эта статья — про твою сторону процесса: какой скилл звать, что
подготовить, какие вопросы прилетят и что ты получишь на выходе.

---

## С чего всё начинается: паспорт проекта

Первый запуск в свежем форке — всегда **`/setup-fork`**. Это интервью
(авторизация, роли, URL, спека, БД, конвенции кодов, охват слоёв),
по итогам которого появляются `src/auth.py`, адаптированный
`Tests/conftest.py`, ключи в `.env.example` и главное — **паспорт проекта
`docs/project-profile.md`**: постоянная память, которую все остальные
скиллы читают вместо того, чтобы переспрашивать тебя.

Пока паспорта нет, любой рабочий скилл откажется работать одной фразой
«запусти /setup-fork» — это защита от тестов, написанных по догадкам.
Скилл идемпотентен: когда появится фронтенд или мобилка, запусти его
снова — он дополнит паспорт, не трогая уже настроенное.

Ответ «не знаю» в интервью — нормальный: пункт попадёт в «Открытые
вопросы» паспорта, а не превратится в молчаливую догадку. Пароли агент
в чат не просит никогда — значения секретов вписываешь ты и только в `.env`.

## Карта скиллов: что просить и у кого

| Твоя задача | Скилл | Пример запроса |
|---|---|---|
| Настроить форк / обновить паспорт | `/setup-fork` | «подключи фреймворк к нашему API» |
| Тесты на один ресурс/эндпоинт API | `/api-tests` | «покрой тестами ресурс contracts по тегу Contracts» |
| Покрыть ВЕСЬ API по спеке | `/api-suite` | «собери регрессию по всему сваггеру» |
| UI-тест на страницу/сценарий | `/frontend-tests` | «покрой тестами форму создания пользователя в админке» |
| Мобильный тест на экран/фичу | `/mobile-tests` | «напиши тест на экран логина Android-приложения» |
| Фича сразу на нескольких слоях | `/test-flow` | «покрой фичу из тикета PROJ-123 на API и UI» |
| Проверить СУЩЕСТВУЮЩИЕ тесты | `/review-tests` | «проревьюй Tests/Regression_tests/contracts по чеклисту» |

Скиллы дисциплинированно отфутболивают чужое: попросишь у `/api-tests`
страницу админки — получишь отлуп «этот скилл покрывает только
API-слой», а не кривой тест.
Починка падающих тестов — вне скоупа генерирующих скиллов: это обычный
разговор с агентом, без скилла.

## Как формулировать запрос

**Вводные из запроса агент извлекает и не переспрашивает.** Чем больше
дашь сразу, тем короче интервью:

> «Покрой тестами ресурс tasks: тег спеки Tasks, create возвращает 201,
> список — конверт {data, total}, гонять под ролью admin»

— эти четыре факта уже не спросят. Наоборот тоже работает: скупой запрос
(«покрой tasks») — и агент задаст вопросы по чеклисту или покажет
`--list-tags` спеки на выбор.

**Автономный режим.** Скажи «сделай всё без вопросов» — агент вместо
каждого вопроса зафиксирует ДОПУЩЕНИЕ и продолжит; все допущения соберутся
в отчёте. Это быстрее, но допущения потом проверять тебе — для первого
захода на домен лучше отвечать на вопросы.

## Что подготовить заранее

- **API-слой**: путь/URL OpenAPI-спеки в паспорте. Полную спеку агент в
  контекст не тянет — режет срез скриптом `openapi_slice.py`.
  Спеки нет — готовься отвечать на вопросы о контракте (путь, тело,
  коды, конверт списка, роль).

  состояния без URL (модалки, тосты, шаги визарда) снимаешь ты проходом

  запускается только по твоей явной просьбе.

## Как проходит работа: точки, где нужен ты

1. **Матрица до кода.** Перед первым файлом агент показывает тестовую
   матрицу: что проверяем и откуда каждый факт. Состав источников зависит
   от слоя: в API — спека / паспорт / твой запрос / ДОПУЩЕНИЕ, в UI и
   мобилке место спеки занимает живой дамп. Читай именно колонку
   источников: строки с «ДОПУЩЕНИЕ» — твои будущие сюрпризы на прогоне.
2. **Вопросы пачкой.** В `/api-suite` открытые вопросы всех доменов
   приходят одним нумерованным списком с рекомендуемыми дефолтами и
   влиянием («меняет N тестов домена X») — отвечать на такой список
   сильно дешевле, чем на капающие по одному вопросы.
3. **Гейты `/test-flow`.** Фазовый оркестратор (обсуждение → план →
   выполнение → ревью → итоги) останавливается после каждой фазы и ждёт
   твоего подтверждения; артефакты и журнал лежат в `docs/coverage/<slug>/`.
   Оборвалась сессия — скажи «продолжи <slug>», флоу поднимется из
   журнала, не начиная заново.
4. **Классификация падений.** На живом прогоне агент раскладывает падения
   на три типа: баг теста (чинит сам), расхождение со спекой (вернётся с
   вопросом — НЕ подгоняет ассерт под фактическое поведение), баг стенда
   (пометит `xfail` и отдаст решение тебе). У каждой петли жёсткий лимит —
   бесконечной починки не бывает, упёрся — честный отчёт.

## Что ты получаешь на выходе

Каждый скилл заканчивается отчётом: созданные файлы, покрытие матрицы
(написано / xfail / требует человека), обязательная секция «Допущения и
открытые вопросы», статус verify и прогона. `/review-tests` — особый
случай: он **ничего не правит** (read-only по чеклисту
`references/review-checklist.md`), отдаёт таблицу находок
`файл:строка + пункт + severity`; починка — отдельным шагом по твоей
просьбе.

Найденные в работе особенности ПРОЕКТА (флаки стенда, расхождения доки с
фактом, нестабильные селекторы) агент дописывает в «Копилку ловушек
проекта» соответствующего рецепта `docs/*.md` или в паспорт — так опыт
накапливается и следующие запуски не наступают на те же грабли.

## Чего агент не сделает (и это фича)

- Не начнёт писать тесты без паспорта и не выдумает семантику API,
  селектор или мобильный идентификатор — источники только спека, паспорт,
  твой запрос и живые дампы.
- Не тронет `example_*`-эталоны, чужие домены и инфраструктуру.
- Не закоммитит без явной просьбы и не попросит секреты в чат
  (хардкод URL/паролей дополнительно блокируется хуком —
  см. секцию «Safety hook» в CLAUDE.md).
- Не будет чинить бесконечно: у каждой петли лимит, дальше — отчёт.
