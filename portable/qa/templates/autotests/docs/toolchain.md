**Пришли на новую машину — вам сюда.** Файл отвечает на один вопрос: что должно
стоять, чтобы репозиторий работал целиком. Он описывает ПРОЕКТ, а не конкретный
ноутбук: лежит в git и приезжает вместе с репозиторием.

Что где лежит, чтобы не искать:

| Вопрос | Ответ |
|---|---|
| Что поставить на новую машину | этот файл, таблица ниже |
| Что стоит на ЭТОЙ машине прямо сейчас | `.preflight-ok` — пишется прогоном, привязан к хосту, в `.gitignore` |
| Как проект устроен (сервисы, роли, домены, конвенции) | `docs/project-profile.md` (заводит `/setup-fork`) |

**Читать таблицу глазами не нужно** — её разбирает `preflight.py` и сам
печатает по каждой недостаче колонки «без неё» и «ставить». Скиллы берут
формулировку закрытого класса работ из ВЫВОДА ПРОГОНА, а не отсюда.

## Как заполнять (форк правит таблицу под себя)

Одна строка — один инструмент. Колонки:

- **Что** — имя строки, оно же ключ в маркере. Меняешь имя — маркер считает
  строку новой.
- **Как проверить** — одна команда, по коду возврата которой судим. Пусто (`—`)
  → строка проверяется только по колонке «Путь».
- **Путь** — файл или каталог. Проверяется ТОЛЬКО отсюда: пути из прозы
  разбирать бесполезно. Поддерживает `~`, `${VAR}` и `${VAR:-канон}`, значения
  берутся из окружения, затем из `.env`.
- **Минимум** — минимальная версия; пусто → версия не важна.
- **Без неё** — КАКОЙ КЛАСС РАБОТЫ закрывается. Это главная колонка: её печатает
  прогон, по ней агент называет человеку, что теперь недоступно. Пишите
  следствие («мобильный слой закрыт целиком»), а не факт («нет Node»).
- **Как ставить** — команда установки и ОС. Ставит ЧЕЛОВЕК: ни скрипт, ни агент
  ничего в систему не приносят.
- **Переменные** — имена переменных `.env`, без которых строка не работает.
  Прогон называет ПУСТЫЕ по имени (сначала окружение, потом `.env`), значений не
  печатает. Агенту `.env` обычно закрыт — «заполнен ли он» он узнаёт отсюда, а
  имена переменных — из этой колонки. Пусто (`—`) → не проверяется.

Строки, где всё «?», пропускаются — незаполненный шаблон это не оснащение.

## Оснащение машины  ← ПРОВЕРЯЕТСЯ СКРИПТОМ, НЕ ГЛАЗАМИ

```bash
preflight.py                # полный прогон
preflight.py --use-marker   # гейт на входе в скилл: молчит, пока ничего не менялось
```

Скопируйте нужные и заполните пути под свой проект — формулировки «Без неё»
уже написаны так, как их полезно услышать от прогона.

| Слой | Строки |
|---|---|
| API-тесты | файл OpenAPI-спеки из паспорта — без него не работают `openapi_slice.py` и `api_client_check.py`, то есть `/api-tests`, `/api-clients`, `/api-suite` закрыты |
<!-- слой: frontend -->
| Фронтенд | браузер (`/Applications/Google Chrome.app` на macOS) — без него `/frontend-tests` и дамп страницы не на чем гонять. Плюс строка «Стенд фронтенда» с колонкой «Переменные»: `FRONTEND_BASE_URL` и переменные кредов UI-логина проекта |
<!-- /слой -->
<!-- слой: mobile -->
| Мобилка | Node (18+) → Appium (3.0+) с драйверами `uiautomator2`/`xcuitest`; `adb` для Android, Xcode для iOS. Без Appium `/mobile-tests` и `dump_ui_tree.py` не работают. Плюс строка «Устройство» с колонкой «Переменные»: `PLATFORM`, `IOS_UDID`, `IOS_APP_PATH`, `IOS_BUNDLE_ID` (iOS) или `PLATFORM`, `ANDROID_DEVICE_NAME`, `APK_PATH` (Android) — без них живого прогона и прохода по сценарию нет |
<!-- /слой -->
<!-- слой: ui -->
| Локаторы в коде продукта | клоны репозиториев продукта (`docs/apps-repos.md`) плюс их тулчейн: пакетный менеджер фронтенда для проверок админки, менеджер SDK и сам SDK для мобилки. Без них `/keys-admin` и `/keys-mobile` невозможны |
<!-- /слой -->

**Чего сюда намеренно не кладут.** Оболочку, `git`, `curl` — без них не работает
ничего, и это видно с первой команды. Инструменты, чьё отсутствие закрывает не
класс проверок, а удобство (сборщик отчётов): сырые результаты прогона остаются
на месте. Поднятый сервер, запущенный симулятор, собранное приложение — это
момент времени, а не оснащение: поднимаются по требованию перед прогоном.
