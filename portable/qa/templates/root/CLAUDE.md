# {{title}} — QA-проект (корень)

Работа идёт **отсюда, из корня**: папки проекта лежат в нём, куда за чем идти и кого звать — ниже.
<!-- слой: git_root -->
Проект — один git-репо: папки лежат в нём, своих `.git` у них нет. Пуш один: `git push` из корня.
<!-- /слой -->
<!-- слой: git_repos -->
У каждой папки свой git-репо: коммит и пуш — в её папке (`git -C <папка> …`).
<!-- /слой -->

**Правила работы — скилл `qa:rules`.** Вызови его в начале сессии, до первой работы с вики, спекой,
коллекцией или трекером: там «сам или помощник», поиск, ингест, коммиты и политика трекера.

С человеком говори на его языке — с первой реплики, со скиллом и без.

**Скилла `qa:rules` нет среди доступных — плагины проекта на этой машине не стоят.** Скажи человеку
об этом первой строкой ответа, до работы: без них нет правил проекта и скиллов. Поставить — из корня,
каждый плагин из `enabledPlugins` в `.claude/settings.json`:
`claude plugin install <плагин>@qa-toolkit --scope project`, потом перезапустить `claude`.

**Скилла или команды из этой карты нет (`Unknown skill`, команда не найдена) — плагин на этой машине
старее проекта.** Работу скилла руками не делай: скажи человеку и спроси, обновить ли сейчас. Обновить —
из корня: `claude plugin marketplace update qa-toolkit`, потом для каждого плагина из `enabledPlugins`
`claude plugin update <плагин>@qa-toolkit --scope project`; новая версия заработает со следующей сессии.

## Кого звать

| Задача | Чем |
|---|---|
<!-- слой: kb -->
| Вопрос по продукту, «где про X» | `qa:kb-query`: страницы вики читает сам, поиск и сырьё отдаёт разведчику |
| Ингест документов в вики, проверка вики | `qa:kb-ingest`, `qa:kb-lint` |
| Человек дал задачу («возьми в тест», «в работу», «задача вернулась», «покрой тестами экран X», «добавь локаторы на Y») — первым, до скилла работы из строк ниже | `qa:task`: заведёт карточку задачи и сам позовёт скилл работы |
| «Что дальше?», «на чём остановились?» — продолжить; «что по задачам?», «что висит?» — обзор | `qa:next`, `qa:progress` |
| Перепроверка задачи, поиск UI-багов, заведение бага в трекер | `qa-manual:task-recheck`, `qa-manual:ui-bug-sweep`, `qa-manual:tracker-filing` |

<!-- /слой -->
<!-- слой: frontend -->
| Тесты веб-страниц; локаторы `data-testid` в коде админки | `qa-auto:frontend-tests`, `qa-auto:keys-admin` |
<!-- /слой -->
<!-- слой: mobile -->

известные баги из вики. Нужное из соседней папки — бери, не спрашивая, в какой она репе.

## Как работать из корня

<!-- слой: autotests -->
- **Команды автотестов — в их папке:** `cd {{autotests}} && make verify`,
  `cd {{autotests}} && .venv/bin/python -m pytest …`. Их `.venv` и `.env` лежат там же.
<!-- /слой -->
- **Субагент работает в корне**, как и ты. В задании давай ему пути от корня, с папкой в начале, и
  первым действием — прочитать `CLAUDE.md` нужной папки.
- **Коммит — по одной зоне.** Задача задела две зоны — два коммита подряд; префиксы — в `qa:rules`.
  Зоны:
<!-- слой: git_root -->
  - корень — карта, `.gitignore`, `.claude/`;
<!-- /слой -->
<!-- слой: kb -->
  - `{{kb}}/{{wiki}}/`, `{{kb}}/{{collection}}/` и прочее `{{kb}}/` — три зоны;
<!-- /слой -->
<!-- слой: autotests -->
  - `{{autotests}}/`.
<!-- /слой -->
- **Пуш — только после «да» человека.**
