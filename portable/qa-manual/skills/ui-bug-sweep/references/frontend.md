# Прогон фронта в браузере

> Открывай, **когда предстоит идти на стенд браузером**: правила прогона, куда пишутся
> находки и что несёт скилл `ui-bug-sweep`. Пути здесь — от корня репозитория проекта, кроме
> `references/…` — они от папки скилла.

Процедура прогона — скилл **`ui-bug-sweep`**, универсальный, живёт в плагине `qa-manual`
(единственный канонический источник). Режимы: поиск новых багов, перепроверка записанных, прогон
тест-кейсов, регресс после релиза.

Заполните адреса стендов в `project-passport.md` и `site-notes.md`. Ходите туда встроенным
браузером Claude или скриптами скилла — навигация, клики, DOM, консоль, сеть. Находки
складываются в страницу реестра фронтовых находок в `status/` страниц вики (папку печатает
`qa-paths pages`, команда плагина `qa`) — с собственной
нумерацией, отдельной от нумерации бэковых багов. Заведите её при первом прогоне, а имя и
путь запишите в **раздел 11 `project-passport.md`** («Куда находки»). В этот файл проектных
значений не вписывают: справочник едет с плагином, общим для всех проектов.

**Правила прогона:**

- **Сверяй фронт с API, прежде чем звать это багом.** «Каталог не показывает товар» и
  «API не отдаёт товар» — разные дефекты с разными исполнителями. `curl` к API +
  `python3 -m json.tool` решает вопрос за один шаг.
- **Перепроверяй находку перед записью.** Часть «багов» — артефакты автоматизации:
  синтетический `Enter` может не дойти до формы, снятие текста страницы — снять
  недогруженный DOM или середину анимации счётчика. Что не подтвердилось — пиши в раздел
  «Проверено и НЕ подтвердилось», иначе следующая сессия заведёт это заново.
- **Пароли не вводишь, пока паспорт проекта (раздел 7) не разрешает вход в окне браузера.**
  Логинится человек сам в панели браузера, дальше работаешь в его сессии. Отправка форм (регистрация, обратная связь) — только с явного разрешения.

Что внутри скилла: критерии «баг / не баг / спорно», каталог приёмов (переходы, адаптив,
состояния, роли, сверка с API), формат находки, разбор каналов (`references/channels.md`)
и несколько скриптов без зависимостей для скриншотов, обхода площади и пошагового
интерактива через CDP.

## Специфика проекта сильнее общих критериев

**Специфика проекта — `site-notes.md` в корне репозитория.** Скилл читает его перед
прогоном, и он **сильнее** общих критериев: что там названо ожидаемым, багом не считается.

**Дописывать после каждого прогона.** Любой ответ человека в духе «это у нас так
задумано» идёт туда сразу — иначе следующая сессия принесёт тот же вопрос. Шаблон, если
понадобится сверить структуру, — `references/site-notes-template.md`.

## Каналы к фронту — куда смотреть за подробностями

Сравнение каналов доступа к фронту (встроенный браузер, debug Chrome + CDP-скрипты,
скриншоты, дампы) — какой инструмент когда использовать, их стоимость в токенах и время —
универсальное README `references/channels.md` в скилле `ui-bug-sweep`. Не дублируем здесь:
если проведёте собственный замер на новом проекте — обновляйте тот файл (он общий для всех
проектов, использующих этот скилл), а проектные капканы (авторизация, вьюпорты, порты) —
в `site-notes.md`.
