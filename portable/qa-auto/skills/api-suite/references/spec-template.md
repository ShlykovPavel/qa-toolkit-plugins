# Формат поведенческой тест-спеки домена (spec-template)

Шаблон для агента `test-spec-writer`. Спека — ПОВЕДЕНЧЕСКАЯ: описывает,
«что должно происходить» при действиях над ресурсом, и фиксирует всё
неизвестное как открытые вопросы. Спека — источник правды для writer'а
поверх среза: writer не гадает, он читает спеку.

Источников два: срез OpenAPI (секции 1–6) и срез базы знаний проекта
(секция 7) — правила, кейсы, баги и оговорки, которых в сваггере нет.

**Эталон различия «поведенческая vs пересказ среза»:**

- Поведенческая строка (нужна): «повторный POST с тем же уникальным
  полем → 400/409 (открытый вопрос q2: какой код — в срезе не описано)».
- Структурный пересказ (бесполезен, в спеку НЕ писать): «POST /tasks
  принимает поля name, description» — это уже есть в срезе, спека
  не должна его дублировать.

Правило заполнения: все секции обязательны. Если по секции сказать
нечего — явная строка «нет / не применимо / в срезе отсутствует»,
а не пропуск секции: отсутствие информации — тоже информация.

---

## Шапка

```markdown
# Тест-спека домена <Ресурс>

Срез: <путь к файлу среза> · Операций: <N> · Дата: <YYYY-MM-DD>
База знаний: <путь к срезу вики> | не передана
```

## 1. Операции и коды

Только ИЗ СРЕЗА — никаких шаблонных догадок («update обычно 200»).
По каждой операции: что она означает поведенчески и какие коды когда.
Отсутствующие CRUD-операции — ЯВНОЙ строкой (например: «DELETE в срезе
ОТСУТСТВУЕТ»), с последствиями в секциях 5 и 6. Код, которого нет
в срезе, но который нужен тестам (404 на несуществующий id, 400 на
невалидное тело), — открытый вопрос, не допущение.

## 2. Конверт списков и пагинация

Из паспорта и среза: голый массив или обёртка (`items/total/...`),
параметры пагинации и фильтров, поведение при пустом результате.
Конвенции могут различаться между ресурсами — не обобщать чужие.

## 3. Связи ресурсов

Parent/child (чей id нужен для создания), каскады при удалении
родителя, ссылки на другие домены. Нет связей — явная строка.

## 4. Граничные значения полей

Только то, что даёт срез (required, minLength/maxLength, enum, format,
типы id) — и что из этого следует для тестов: какое невалидное тело
обязано дать 400, какие границы стоит дёрнуть. Ограничение не описано
в срезе — открытый вопрос, если оно важно для матрицы.

## 5. Teardown-стратегия

Что удаляем после тестов и ЧЕМ. Первый вопрос секции: есть ли delete
ВООБЩЕ? Если нет — фикстуры без удаления, риск накопления данных на
стенде записывается здесь И дублируется открытым вопросом (чем чистить:
недокументированный эндпоинт? прямой доступ к БД? TTL стенда?).

## 6. Открытые вопросы

Таблица — обязательно непустая на реальном домене (домен без единого
вопроса — повод перепроверить, а не гордиться):

```markdown
| id | Вопрос | Рекомендуемый дефолт | Влияние |
|---|---|---|---|
| q1 | ... | ... | меняет N тестов блока X |
```

- `id` — сквозной в рамках домена (q1, q2, ...), на него ссылаются
  строки других секций.
- «Рекомендуемый дефолт» — то, что writer примет в автономном режиме
  как допущение (дословно).
- «Влияние» — что изменится при другом ответе: какие тесты/фикстуры
  и сколько.
- Вики и срез спеки расходятся (код, поле, статус, лимит) — это вопрос
  сюда, обе позиции со ссылками («сваггер: 400; вики `flows/…`, ## Ошибки,
  от <дата>: 409»), а не выбор одной из них молча.

## 7. Из базы знаний

Только то, чего НЕТ в секциях 1–4, — сваггер здесь не пересказывать.
Среза вики нет — строка «база знаний: не передана»; эндпоинт домена в
списке `empty` среза — строка «в вики по <эндпоинт> ничего нет».

```markdown
| id | Проверка | Откуда | Статус |
|---|---|---|---|
| k1 | заказ дороже лимита корзины → 400 `CART_LIMIT` | `flows/flow-zakaz.md`, ## Правила и лимиты, 2026-09-18 | проверяем |
| k2 | отмена оплаченного заказа возвращает деньги | BUG-7 (PRJ-120), `status/status-bagi.md` | ожидаемо падает |
| k3 | повторная отмена → 409 | TC-04 `tests/test-zakaz.md`; BUG-3 закрыт | проверяем, регресс |
| k4 | частичная отмена позиции | `flows/flow-zakaz.md`, ## Планы | TO-BE — не проверяем |
```

- Проверка — поведенческая строка, как в секциях 1–4, с кодом и полем,
  если вики их называет.
- «Откуда» — страница и раздел, номер кейса `TC-NN` или бага, и дата
  страницы (`updated`): вики может отставать от кода, дата решает спор.
- Статусы:
  - `проверяем` — правило действует, тест пишется;
  - `проверяем, регресс` — закрытый баг: тест держит починку;
  - `ожидаемо падает` — открытый баг по эндпоинту; новый баг-репорт на
    это не заводится, `xfail` со ссылкой ставится только после «да»
    человека на плане (баг мог починиться, а вики — отстать);
  - `TO-BE — не проверяем` — задумано, но не сделано;
  - `не автоматизируем — <почему>` — оговорка стенда («только в БД»,
    «необратимо на общем стенде»); необратимое — ещё и риск в секции 5.
- Кейсы `TC-NN` вики, которые покрывает проверка, — в «Откуда»: по ним
  потом считается, какие кейсы вики автоматизированы.
