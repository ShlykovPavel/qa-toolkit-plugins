# Чеклист адверсарного ревью тестового слоя

Источник правил: `docs/tests.md`, `docs/api-layer.md`, `docs/frontend.md`,
`docs/mobile.md`, `CLAUDE.md`. Ревьюер ИЩЕТ НАРУШЕНИЯ, а не подтверждает
качество. Каждая находка оформляется как: `файл:строка` + номер пункта +
severity (`high` / `med` / `low`).

Пункты 1–12, 23 и 25 — общие и API-слой; 13–17 — фронтенд (применять к
`frontend/` и `Tests/Frontend_tests/`); 18–22 и 24 — мобилка (применять к
`Appium/` и `Tests/Mobile_tests/`). Номера не переставляются: новые пункты
получают следующий номер в конце своей секции, чтобы ссылки из отчётов и
уроков не съезжали. Слоя нет в проекте — его секция пропускается с явной
строкой в отчёте.

## Пункты: общие и API-слой

1. **Хардкод URL / кредов / секретов** — любые литеральные URL стенда,
   пароли, токены, API-ключи в коде тестов или клиентов. Разрешено только
   чтение из `config.py` (env-переменные). — **high**
2. **Scope фикстур** — фикстура со `scope='session'` (или `module`),
   создающая тестовые данные. Сессионный scope допустим только для
   авторизации/подготовки окружения. — **high**
3. **Teardown / cleaner на всё созданное** — каждый созданный ресурс либо
   удаляется через yield-teardown фикстуры, либо зарегистрирован в
   `*_cleaner`. Тест без teardown-гарантии — находка. Teardown должен быть
   терпимым (try/except), а отказ уборки — громким: `report_teardown_failure`
   из `src/teardown_utils.py`, не `print` (pytest выбрасывает stdout
   прошедших тестов, и утечка становится невидимой; `print` в except
   teardown — находка **med**). Гарантия действует С МОМЕНТА СОЗДАНИЯ:
   если между созданием ресурса и `yield` (или регистрацией в cleaner)
   есть шаги, способные упасть (поиск id, получение кода, логин), —
   ресурс регистрируется в cleaner сразу после создания либо эти шаги
   обёрнуты в `try/finally` с удалением. Иначе падение в этом окне
   оставляет ресурс на стенде: teardown фикстуры, упавшей до `yield`, не
   выполняется. — **high**
4. **Уникальные данные** — имена/email/телефоны только из
   `src/data_generators.py`; фиксированные строки-имена ресурсов ломают
   параллельный прогон. — **med**
5. **Allure-разметка и pytestmark** — модульный `pytestmark`
   (`regression`/`smoke`), `@allure.epic` + `@allure.feature` на классах,
   `@allure.description` на тестах. — **med**
6. **Независимость тестов** — тест читает данные, созданные другим тестом;
   общие словари/модульные переменные для передачи данных между тестами. —
   **high**
7. **Негативы через `status_code=`** — негативный вызов обязан передавать
   ожидаемый код через `status_code=`; результат такого вызова — `None`,
   разыменование (`result['id']`) — находка. — **high**
8. **Коды и конверты из спеки, не из шаблона** — коды ответов и структура
   конверта списка сверяются со СРЕЗОМ спеки домена (если срез доступен —
   сверить!); скопированные из эталона «типовые» 200/204 или защитный
   `response.get('data', response)` без сверки — находка. — **med**
9. **`access=` вместо ручных токенов** — токены не передаются руками и не
   кладутся в заголовки в обход `HttpClient`; роль — параметром
   `access="<роль из паспорта>"`. — **high**
10. **conftest домена существует** — в директории домена есть свой
    `conftest.py` с фикстурами домена и `__init__.py`; фикстуры не
    свалены в сессионный `Tests/conftest.py`. — **high**
11. **`example_*` не тронуты** — файлы-эталоны (`src/example_resource/`,
    `Tests/**/example_*`, `example_swagger.json`) и `docs/*.md` не
    изменены. Исключения — правки, которые предписывают сами генерирующие
    скиллы: дозапись в секцию «Копилка ловушек проекта»
    (`docs/api-layer.md`, `docs/frontend.md`, `docs/mobile.md`) или в
    паспорт `docs/project-profile.md`. Проверь, что такая правка — дозапись в свою
    секцию, а не переписывание остального текста; правка за пределами
    секции — находка. — **high**
12. **`time.sleep` / try-except вокруг ассертов** — ожидание только через
    `wait_until()`; try/except, глотающий ассерты «чтобы не падало», —
    находка. Слепые паузы (`time.sleep`, `asyncio.sleep`,
    `wait_for_timeout`) ловит механически `scripts/check_no_sleep.py` в
    `make verify`; ревьюер добивает то, что скрипт не видит: пауза через
    обёртку, поллинг с блокирующим условием, съедающим таймаут. — **med**
23. **Фикстура — только предусловия и teardown** — действие, которое тест
    ПРОВЕРЯЕТ (UI-сценарий, целевой вызов API), вынесено в conftest-фикстуру
    «для чистоты теста». Его падение всплывает как ERROR фикстуры, а не
    FAIL теста, и тело теста читается так, будто это предусловие. Шаги
    сценария живут в теле теста или в Module/клиенте, вызванном из тела. —
    **med**
25. **Правка проверена чтением, а не ответом** — тест PUT/PATCH сверяет
    только ответ самой правки, или перечитывает ресурс (get/список), но
    часть изменяемых полей оставляет с прежними значениями. API может
    ответить новыми значениями и хранить старые — такой тест баг
    сохранения пропустит. Каждое изменяемое поле получает новое значение
    и сверяется чтением после правки в том же тесте (у PATCH — ещё и
    нетронутость непереданных полей). — **med**

## Пункты: фронтенд (Selenium / Playwright)

13. **Приоритет селекторов** — у элемента есть `data-testid`, а селектор
    не по нему (`docs/locator-conventions.md`: тесты ищут по стабильным
    id, по видимому тексту — никогда) — находка; это главнее лестницы в
    `docs/frontend.md` проекта. Ключа нет — по лестнице СВОЕЙ ветки
    (selenium — id → name → css → xpath → link_text; playwright —
    get_by_role → get_by_label → get_by_placeholder → css-резерв):
    селектор ниже самого высокого ДОСТУПНОГО якоря — находка. — **med**
14. **Хрупкие селекторы помечены техдолгом** — селектор по тексту,
    индексу, длинному/позиционному xpath без комментария-техдолга рядом
    (что попросить у фронтов: data-testid / role / label). — **med**
15. **Page object без логики** — в page object только локаторы
    (`@property`; selenium — с `finder_type` по смыслу элемента);
    ассерты, ветвления, действия-сценарии в page object — находка. —
    **med**
16. **Ветки не смешаны** — selenium-тест не использует `page`/`expect`,
    playwright-тест не использует `driver`/ButtonFinder; page object
    не задублирован в чужой ветке. — **high**
17. **Браузер только в function-фикстуре** — драйвер/страница не
    создаются на уровне импорта или класса (коллекция падает без
    браузера); предусловия данных — через API-клиенты `src/`, не через
    UI-прокликивание. — **high**

## Пункты: мобилка (Appium)

18. **Наследование от `ScreenActions`** — классы app_keys наследуют
    `ScreenActions` (НЕ `BaseElements`), в них только локаторы:
    статичные элементы — `@property`, параметризованные — методы;
    «голые» идентификаторы без `<package>:id/`. — **high**
19. **Семантика `element_expected`** —
    `get_element(key, element_expected=False)` — это АССЕРТ ОТСУТСТВИЯ,
    элемент он не возвращает никогда; использование «достать элемент,
    если есть» — находка. — **high**
20. **Проверка отсутствия — `is_element_not_presented`** — отсутствие/
    исчезновение элемента ассертится через
    `is_element_not_presented(key)`, не через try/except вокруг
    `get_element` и не через `element_expected=False` с разыменованием. —
    **high**
21. **Текст — не локатор; локализация** — поиск по видимому тексту,
    XPath-по-структуре и координатам запрещён (единственное исключение —
    системные диалоги ОС); текстовые проверки — по ключам локализации
    (`assert_text`), хардкод отображаемых строк — находка. — **high**
22. **`Logger.log_mobile_action` на каждое действие модуля** — методы
    Module логируют каждое взаимодействие (главный источник диагностики
    самого медленного слоя); действия без лога — находка. — **med**
24. **Сохранённое состояние приложения сбрасывается** — тест, который
    доводит приложение до состояния, переживающего перезапуск (вход,
    заданный PIN, сессия, принятые согласия), сам возвращает устройство в
    исходное: сброс данных приложения в teardown (на iOS-симуляторе —
    переустановка приложения), драйвер с полным сбросом или явное
    требование чистой установки, которое проверяется в начале теста.
    Общая фикстура `driver` данные приложения между тестами не чистит, и
    без этого второй прогон падает уже на стартовом экране. — **high**

## Формат отчёта ревьюера

- Таблица находок: `№ | файл:строка | пункт | severity | что нарушено`.
- Отдельно: пункты, проверенные без находок (подтверждение покрытия чеклиста).
- Итог: количество high/med/low.
