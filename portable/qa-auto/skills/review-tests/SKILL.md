# Адверсарное ревью тестов (review-tests)

Вход — директория/домен (`Tests/Regression_tests/contracts/`), слой
(«фронтенд-тесты») или «всё». Выход — структурированный отчёт находок.
Это ревью КОНВЕНЦИЙ ЭТОГО ФРЕЙМВОРКА по чеклисту, не general code review.

## Шаг 0 — Pre-flight (первым действием, до любой другой работы)

| Ситуация | Действие |
|---|---|
| В проекте нет тестов вне `example_*`-эталонов (проверь `Tests/`) | Одной фразой: «ревьюить нечего — в проекте нет своих тестов; новое покрытие — /api-tests, /frontend-tests, /mobile-tests» — и СТОП. |
| Запрос «напиши/сгенерируй тесты» | Одной фразой отошли к генерирующему скиллу слоя (/api-tests, /frontend-tests, /mobile-tests) и верни управление. |
| Запрос «почини/отладь падающий тест» | Одной фразой скажи, что скилл делает ревью по чеклисту, а починка — вне его скоупа; верни управление. |
| Запрос про general code review продукта/PR не про тестовый слой | Одной фразой скажи, что скилл ревьюит только тестовый слой этого фреймворка по чеклисту конвенций; верни управление. |
| Иначе | Определи скоуп: названные директории/домен/слой; «всё» = все домены `Tests/` + их клиенты `src/` + `frontend/` + `Appium/` (кроме `example_*`). Работай дальше. |

## Шаг 1 — Чеклист и контекст

Прочитай `references/review-checklist.md` (единственный источник пунктов —
никаких собственных вкусовых правил). Пункты 1–12 — всегда; секции фронтенда (13–17) и мобилки
(18–22) — если слой есть в скоупе. **«Слой есть» = есть ЛЮБЫЕ его файлы
вне `example_*`** — page object'ы, app_keys, Modules, локаторы; проверь
листингом `frontend/` и `Appium/`, а не по наличию тестов слоя:
отсутствие самих тестов секцию НЕ выключает (модули и локаторы ревьюятся
тоже). Пропущенный слой отметь явной строкой в отчёте — с причиной
«файлов слоя нет», а не «тестов нет». Дополнительный контекст: `docs/tests.md`,
`docs/api-layer.md`, `docs/frontend.md`, `docs/mobile.md`, паспорт
`docs/project-profile.md` (если есть) и срез спеки домена (пункт 8 —
сверять, только если срез доступен).

## Шаг 2 — Ревью (адверсарно, read-only)

Исходи из того, что нарушения ЕСТЬ, и докажи их наличие — или честно
зафиксируй отсутствие по каждому пункту. Пункт за пунктом, по каждому
файлу скоупа. Каждая находка: `файл:строка` + номер пункта + severity
(`high`/`med`/`low`) + одна строка «что нарушено».

**РЕЖИМ РЕВЬЮ = READ-ONLY. Write/Edit на файлы тестов, клиентов,
фикстур, page object'ов и локаторов ЗАПРЕЩЕНЫ КАТЕГОРИЧЕСКИ.** Нашёл
«очевидную мелочь на две секунды» — НЕТ, не правь: она идёт в отчёт,
как и всё остальное. Ни «заодно поправлю», ни «это же безопасно», ни
автономный режим этого не отменяют. Правка найденного — ОТДЕЛЬНЫЙ второй
шаг, который выполняется только по явной просьбе пользователя ПОСЛЕ
отчёта (и это уже не режим ревью). Bash — только read-only команды
(grep/ls/cat/git diff); ничего не коммитить, `example_*` и `docs/*` не
трогать.

## Шаг 3 — Отчёт

Отчёт — финальное сообщение, **ровно по образцу ниже**: заголовки разделов,
столбцы таблицы, вид строк итога и ловушек, закрывающая строка — как в
образце, своими словами — только ячейки и текст после двоеточий. Перед
отчётом можно одну-две фразы ответа на вопрос пользователя. Формат в
`references/review-checklist.md` — короткий, для агента `test-reviewer`;
отчёт этого скилла — по образцу.

```
## Находки

| № | файл:строка | пункт | severity | что нарушено |
|---|---|---|---|---|
| 1 | `src/<домен>/<файл>.py:18` | 1 | high | одна строка: что нарушено |

## Проверено без находок

- пункты: 4, 5, 7, …
- мобилка (18–22, 24): пропущена — файлов слоя нет

## Вне чеклиста

- <замечание с `файл:строка`> | замечаний нет

## Итог

high: N, med: N, low: N. Круг доработки: нужен (есть high) | не нужен.

## Ловушки проекта

<сигнатура> → <как избегать> → внести: «Копилка ловушек проекта» `docs/<api-layer|frontend|mobile>.md` | паспорт `docs/project-profile.md` | ловушек проекта нет

Код не правился (режим ревью); нужна починка найденного — скажи, что чинить, сделаю отдельным шагом.
```

- **Проверено без находок** — каждый пункт чеклиста, у которого нет
  находки; пропущенная секция слоя — строкой с причиной «файлов слоя
  нет», а не «тестов нет».
- **Вне чеклиста** — правдивое замечание, которого нет в чеклисте
  (не находка: в таблицу не идёт).
- **Ловушки проекта** — особенность стенда, флаки, расхождение доки с
  фактом: то, на что наступит любой, кто будет писать тесты этого проекта.
  Находка в тесте («тест взял неверную границу») — в таблицу; ловушка
  («доки и спека расходятся в границе») — сюда, с местом. Сам не пиши:
  ревью ничего не записывает, вносит тот, кто правит тесты.
