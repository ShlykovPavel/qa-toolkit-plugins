# Отчёты заходов

Один заход перепроверки = один файл. Отчёт пишется скиллом `task-recheck` (фаза 6) и живёт
здесь, а не в `wiki/notes/`: заметки — рабочая память базы, отчёты — результат работы,
который человек читает и по которому принимает решение.

## Имя файла

```
otchet-<ГГГГ-ММ-ДД>-<что проверяли>.md
```

Дата первой позицией — чтобы каталог сортировался хронологически сам. Дата — та, **когда
прогон состоялся**, а не когда файл дописан.

| Пример | Что это |
|---|---|
| `otchet-2026-08-12-tracker-32-33-34.md` | заход по трём задачам одного эпика |
| `otchet-2026-08-14-tracker-289.md` | заход по одной задаче |
| `otchet-2026-08-20-regress-katalog.md` | заход не по задаче, а по области |

## Что внутри

Состав разделов задаёт `references/report-format.md` скилла `qa-manual:task-recheck` — здесь он не дублируется, чтобы не разошёлся с источником. Главное, что должно быть видно **сразу**:

- **раздел 0 — вердикт по дефекту**: воспроизводится или нет, в каком объёме, **как закрыт**;
- **раздел 5 — таблица покрытия**: критерий → покрыт → чем именно наблюдался.

Вердикт даётся по дефекту, не по задаче: «дефект не воспроизводится на двух адресах и
пятнадцати записях» — работа агента, «задачу можно закрывать» — решение человека.

## Чего здесь не лежит

| Не сюда | Куда |
|---|---|
| тест-кейсы захода | `wiki/tests/zadachi/` |
| кейсы по флоу | `wiki/tests/` |
| находки фронта и бэка | `wiki/status/status-bagi-front-ui.md`, `status-bagi.md` |
| «так задумано» | `site-notes.md` в корне репозитория |
| сырьё прогона (дампы, `evidence.json`, скриншоты) | не в вики: живёт в каталоге захода, в базу едут выводы |

**Отчёт ссылается на кейсы, а не пересказывает их.** Дублирование расходится через две сессии.
