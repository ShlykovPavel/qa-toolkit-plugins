# Playwright MCP: живая страница как глаза агента

Официальный MCP-сервер проекта Playwright (Microsoft) даёт AI-ассистенту
(Claude Code) управляемый браузер: открыть страницу, снять снапшот
доступности, кликнуть, заполнить форму, прочитать консоль и сеть. Для
тестировщика это значит: агент может САМ пройти сценарий в админке и снять
селекторы с живого DOM — без ручного снятия дампов.

Как MCP встраивается в процесс написания фронтенд-тестов шаблона —
[../frontend.md](../frontend.md), секции «Глаза» и «Рецепт В».

## Что это

| Параметр | Значение |
|---|---|
| Пакет | npm `@playwright/mcp` (актуальная версия на 2026-07-18 — 0.0.78) |
| Репозиторий | https://github.com/microsoft/playwright-mcp (официальный) |
| Транспорт | stdio; браузер ставится playwright'ом (chromium по умолчанию) |
| Принцип | **снапшот доступности, не скриншот**: агент видит страницу текстовым деревом ролей/имён с ссылками на элементы — дёшево по токенам и точно |

Версия 0.0.x — API до стабилизации; в конфиге **пиновать версию**
(`@playwright/mcp@0.0.78`), при обновлении перепроверять набор тулов.

## Почему это особенно хорошо для playwright-ветки

Снапшот сервера — то же дерево доступности, на котором построены локаторы
Playwright. Роль и accessible name элемента из снапшота — это готовые
аргументы `get_by_role(role, name=...)`, верхняя ступень лестницы
локаторов pw-ветки ([../frontend.md](../frontend.md)).
<!-- слой: selenium -->
Для selenium-ветки MCP тоже работает как глаза (осмотр структуры страницы),
но css/id-локаторы из снапшота напрямую не читаются — их сверяй по
`dump_dom.py`.
<!-- /слой -->

## Подключение к Claude Code

```bash
claude mcp add playwright -- npx @playwright/mcp@0.0.78
```

Плюс allowlist инструментов `mcp__playwright` в `.claude/settings.json` —
применяет человек. Нужен node/npx; первый запуск может скачать браузер.

## Что умеет (основные тулы)

**Инспекция (ради чего всё):**

| Тул | Зачем тестировщику |
|---|---|
| `browser_snapshot` | дерево доступности текущей страницы со ссылками на элементы — главный источник role/name-локаторов; модалка или тост на экране попадут в снапшот |
| `browser_find` | найти элемент по описанию — проверка «а находится ли он вообще» |
| `browser_take_screenshot` | скриншот — Claude мультимодален и читает его сам |
| `browser_console_messages` / `browser_network_requests` | консоль и сеть — понять, что страница реально делает (какой API дёргает форма — подсказка для предусловий через API) |
| `browser_evaluate` | JS-инспекция страницы для спорных случаев |

**Прохождение сценария до целевого состояния:** `browser_navigate`,
`browser_click`, `browser_type` / `browser_fill_form`,
`browser_select_option`, `browser_hover`, `browser_press_key`,
`browser_handle_dialog`, `browser_wait_for`, `browser_tabs`.

Это покрывает рецепт В из [../frontend.md](../frontend.md): логин и шаги
ведутся в диалоге («шаг: открыл форму создания» → агент делает/смотрит и
снимает снапшот), состояния без своего URL — модалки, тосты, шаги
визарда — снимаются по ходу.

## Чего НЕ делать

- **Не генерировать тесты «из браузера»**: снапшот — источник локаторов,
  а код пишется по конвенциям шаблона (page object — по
  `docs/frontend.md`, тест в `Tests/Frontend_tests/<Страница>/`).
- **Не подменять MCP-проходом сами тесты**: то, что агент прокликал
  сценарий через MCP, — это осмотр, а не прогон; тест обязан жить в pytest
  и проходить без MCP.
- Ссылки на элементы из снапшота живут только внутри MCP-сессии — в код
  идут локаторы (role/name, testid), а не эти ссылки.

## Грабли

1. **`file://`-навигация заблокирована по умолчанию** (проверено
   2026-07-12): статические file-фикстуры сервером не открыть. Для них —
   дамп скриптом своей ветки (file:// ему не помеха) либо регистрация сервера с
   флагом `--allow-unrestricted-file-access`. Обычных http(s)-страниц
   ограничение не касается. Библиотеки playwright в тестах это НЕ
   касается — там file:// работает.
2. Снапшот большой страницы токеноёмок — осматривай целевой раздел, а не
   гуляй по всему приложению; длинные списки сворачивай фильтрами.
3. Элемент без accessible name (несвязанный label, иконка-кнопка без
   aria-label) в снапшоте безымянный — по role/name его не взять, в дампе
   он хрупкий (`fragile`). Лечится на стороне
   фронта (связать label, дать aria-label/testid) — см. «Что спросить у
   человека» в [../frontend.md](../frontend.md).
4. Версия 0.0.x меняется быстро: набор и схемы тулов не гарантированы —
   пин + ревизия при обновлении.

## Когда MCP, а когда дамп скриптом

| Ситуация | Что брать |
|---|---|
| Интерактивный осмотр: логин, многошаговый сценарий, модалки/тосты — в диалоге с агентом | **MCP** (рецепт В) |
| Нужно понять, какой API зовёт страница (сеть/консоль) | **MCP** |
<!-- слой: selenium -->
| Статическая file-фикстура, окружение без node/npx | **dump_dom.py** |
| Человек снимает дампы сам и отдаёт файлами (агент оффлайн от стенда) | **dump_dom.py** (рецепты А/Б) |
| css-лестница selenium-ветки, нужны кандидаты css-локаторов | **dump_dom.py** (дефолт `--locators css`) |
<!-- /слой -->
<!-- слой: playwright -->
| Статическая file-фикстура, окружение без node/npx | **скрипт на playwright** (`/frontend-tests`, Шаг 2) |
<!-- /слой -->

Правило шаблона: **скилл использует Playwright MCP, если он подключён и
доступен, иначе — дамп скриптом своей ветки**; результат один — локаторы только с живой
страницы. MCP — глаза для ОБЕИХ веток: это инструмент осмотра, не
библиотека тестов.
