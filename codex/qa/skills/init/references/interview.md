# Интервью `/qa:init` и куда пишутся ответы

Источники вопросов — шаги 2–4 онбординга ручника и блоки 3, 4, 7 `setup-fork`; остальное из
`setup-fork` (авторизация, роли, БД, конвенции API) спрашивает он сам.

## Формы

Вопросы задаются этими формами, по порядку, — **как есть**: заголовок, вопрос, варианты и тип
выбора не сочиняешь заново, подставляешь только значения в `<…>` — во всех вариантах, в заданной
форме не остаётся ни одной `<…>`. Первый вариант — ответ по
умолчанию. Свой ответ человек впишет в поле «другое» — форма добавляет его к каждому вопросу сама,
поэтому варианта «укажу в „другое“», «поправлю сам», «отвечу текстом» не бывает: клик по нему
отправляет название варианта вместо ответа (полигоны `init-2`, `init-7`). Вопрос с условием («если
…») задаёшь, только когда условие выполнено; форма без вопросов пропускается. Тип выбора:
**один** — одно значение; **несколько** — верны сразу несколько ответов.

Не спрашиваешь: источник каталога (он из шага 0 — строкой в плане, поправят в ответ на план),
ширину экрана (нужна к первому прогону фронта), значения токенов (только «нужен ли»), политику
доступа к трекеру (по умолчанию любое обращение, и чтение, — по прямой просьбе или после апрува).

| Трекер | Какой трекер задач? | YouTrack · Jira · Трекера нет | один |
| Удалённый репо | Создать удалённый репо проекта (GitHub/GitLab) сейчас? | Нет, только локально · Да — покажи команды отдельным вопросом | один |

**Форма 6 — границы** (обязательна: без неё плана нет)

Черновик — из ответов форм 4–5, и в нём всегда пять пунктов, без «решим позже»:
1. где работаем: прода нет / прод только чтение; внешние сервисы и всё за пределами стенда не трогаем;
2. тестовые данные на стенде агент создаёт и удаляет сам;
3. другое необратимое (деньги, рассылки живым людям, чужие данные) — только с апрувом;
4. секреты — только в `.env`: агент их не читает и не выводит;
5. наружу (чаты, внешние сервисы) — ничего.

Черновик — дословно в тексте вопроса.

| Заголовок | Вопрос | Варианты | Выбор |
|---|---|---|---|
| Границы | Границы агента (раздел 8 паспорта): «<черновик>». Подходят? Свою редакцию — в «другое». | Подходят · Строже: апрув на любое изменяющее действие на стенде | один |

**Доспрос готового проекта** — те же вопросы с теми же вариантами: место из `later` → вопрос по
таблице «Куда пишется» ниже.

## Куда пишется

Пути — от корня своего репо. Заполняются только заглушки (`?`, `<…>`, `ГГГГ-ММ-ДД`).

| Ответ | `kb` | Автотесты |
|---|---|---|
| название, короткое имя, слои, каталог | `plan.json` → `apply` (маркер, settings) | то же |
| название | `CLAUDE.md` — заголовок; `site-notes.md` — заголовок; `wiki/CLAUDE.md` — только имя в заголовке; `project-passport.md` — строка «Проект» и «Обновлено» | — |
| 2–3 предложения о продукте | `CLAUDE.md` — вступление | — |
| стенды, прод | `project-passport.md` — раздел 1 (Фронт, API, Прод); `site-notes.md` — «Стенды», «Обновлено» | вводные `setup-fork` |
| доступ без входа | `site-notes.md` — «Что доступно без входа» | — |
| вход в учётки | `project-passport.md` — раздел 7, строка «Вход агента по паролю» (слова ответа; «решим позже» — `?`: пока входит человек); `site-notes.md` — «Кто логинится» | — |
| спеки | `project-passport.md` — раздел 1 «Спецификация»; «Спеки нет» — там же «Снапшоты спек»: нет | вводные `setup-fork` |
| база знаний, трекер, критерии приёмки | `project-passport.md` — раздел 2, три обязательные строки | — |
| трекер и политика доступа | `CLAUDE.md` — «Трекер», «Политика доступа к трекеру» | — |
| границы | `project-passport.md` — раздел 8 | — |
| слои, библиотека, мобилка | — | `plan.json` → `apply`; вводные `setup-fork` |
| подтверждение человека (шаг 4) | `project-passport.md` — «Подтверждён человеком» | `docs/toolchain.md` — «Обновлено», «Подтверждён» |

Остальные разделы паспорта `kb` (3–7, кроме строки входа, 9, 10) остаются со знаками `?`: это легальное состояние —
незаполненное читается как «возможности нет», дозаполняется по ходу.
