# Установка QA Toolkit агентом

Этот документ описывает пользовательский архив, а не мастерскую разработки.
Установку выполняйте только по просьбе пользователя. Не публикуйте ничего и не отправляйте
журналы автору. Не скачивайте исходники приватной мастерской.

1. Прочитайте README.md и release.json. Определите реальное приложение пользователя
   и доступные ему способы установки локальных плагинов или скиллов.
2. Если архив ещё не скачан, используйте выпуск из публичного репозитория
   https://github.com/ShlykovPavel/qa-toolkit-plugins/releases.
   Через API GitHub доступны метаданные:
   https://api.github.com/repos/ShlykovPavel/qa-toolkit-plugins/releases/latest.
   Выбирайте прикреплённый `qa-toolkit-*.zip`, не `zipball_url` исходников.
   Предварительные выпуски могут отсутствовать в `/latest`: тогда используйте
   указанный пользователем выпуск или список `/releases` и явно сообщите его версию.
3. Скачайте SHA256SUMS из того же выпуска и проверьте SHA-256 архива.
   Контрольная сумма проверяет целостность; сама по себе не удостоверяет автора.
   Распаковывайте с проверкой путей архива в постоянную папку, без перезаписи чужих файлов.
4. Для Claude Code используйте каталог `claude/`, для Codex — `codex/`.
   Команды приведены в README.md. Сначала проверьте поддержку команд через CLI help.
   Наличие команды в этой инструкции не доказывает её поддержку установленной версией.
5. В другом приложении используйте `portable/`: каждый `skills/<имя>/SKILL.md` содержит
   процедуру, `skills/role-*/SKILL.md` — роль помощника. Имена `qa:rules` и подобные
   обозначают пакет и скилл; сопоставьте их с файлами в portable. Сохраняйте соседние
   `bin/`, `references/`, `templates/` и все три пакета. Не копируйте одни SKILL.md.
   Применяйте документированный механизм скиллов вашего приложения. Если его нет,
   читайте нужный SKILL.md по запросу пользователя; не заявляйте постоянную установку.
6. В portable нет автоматических хуков. Claude-специфичные настройки, пути и конфигурация
   нового QA-проекта требуют отдельной адаптации. Не выполняйте Claude/Codex-команды
   для настройки другого приложения и не заявляйте одинаковое поведение всех приложений.
7. Сначала проверьте помощник без создания проекта:
   `python3 <корень-пакета-qa>/bin/qa-hello`.
   Затем в новом чате проверьте загрузку скилла hello. Исполнение скрипта отдельно
   проверяет только скрипт, а не установку скиллов или доверие хукам.
8. Сообщите установленный вариант, версии, результат проверки и ограничения.
   Для нативных вариантов напомните о доверии хукам и локальных журналах из README.

Не меняйте выбранную пользователем модель, не отключайте защиту приложения и не создавайте
проект без просьбы пользователя. Зависимости, креды и подключение внешних сервисов — отдельно.
