# Тест-кейсы под задачу

Кейсы, написанные под конкретную карточку трекера при её перепроверке. Один заход = один файл.

## Чем отличается от `wiki/tests/`

Соседняя папка — кейсы **по флоу**: файл живёт годами, пополняется, покрывает область целиком
(`test-login-registraciia.md`, `test-pokupka-oplata.md`). Здесь — кейсы **под задачу**: снимок
одного захода, привязанный к дословным критериям одной карточки.

Смешивать их нельзя по двум причинам. Файл флоу от этого распухает, а правило базы — один файл
= одна сущность. И нумерация `TC-NN` в файле флоу сквозная и не переиспользуется: вклейка
чужого набора её ломает.

| Что | Куда |
|---|---|
| «проверить регистрацию целиком» | `wiki/tests/test-login-registraciia.md` |
| «перепроверить задачу N» | сюда, `test-<tracker-nnn>.md` |
| кейс из захода оказался нужен всегда | переносится в файл флоу отдельным решением, с новым номером |

## Имя файла

```
test-<tracker-nnn>.md
```

Задач в заходе несколько и они из одного эпика — `test-<tracker>-32-33-34.md`.

## Что внутри

Формат задаёт `references/case-format.md` скилла `qa-manual:task-recheck`. Обязательное, без чего файл не годится:

- **дословные критерии** из карточки в шапке, с указанием, откуда взят каждый — описание или
  комментарий. Пересказ критерия критерием не является;
- у каждого кейса колонка **«исполнитель»**: `агент` / `человек` / `заблокировано`, и она
  **выводится из паспорта проекта**, а не назначается по вкусу;
- у каждого прогнанного кейса — **объём выборки**, а не только итог.

## Связь с отчётом

Отчёт захода лежит в `wiki/reports/` и ссылается сюда. Разделение намеренное: **кейсы говорят,
что делать руками и по чему перепроверять агента; отчёт говорит, чему можно верить и почему.**

Файл кейсов переживает заход. Если задачу перепроверяют второй раз — дописывается новый прогон
в тот же файл, с датой, а не заводится второй файл.
