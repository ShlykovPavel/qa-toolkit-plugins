# Allure на практике: разметка, вложения, отчёты

Allure в этом шаблоне — не украшение, а рабочий инструмент разбора:
правильно размеченный тест сам рассказывает, что он проверял, а хуки
прикладывают к падению улики (запросы, скриншоты, page_source). Статья —
что размечать руками, что прилетает автоматически и как собирать отчёт.

---

## Разметка: три уровня дерева

```python
import allure
import pytest

pytestmark = pytest.mark.regression

@allure.epic("Regression")               # слой: Smoke | Regression | Mobile | Frontend
@allure.feature("Projects")              # фича/домен
class TestProjectsCreate:

    @allure.description("Создание проекта — happy path")
    def test_create_project(self, project_cleaner):
        ...
```

- **epic** — слой прогона; по нему отчёт группирует верхний уровень.
- **feature** — домен/фича; все классы одного домена — одна feature.
- **description** — человеческая фраза «что проверяем»; её читает тот,
  кто разбирает упавший прогон, поэтому пиши проверку, а не пересказ
  имени теста.

Маркер pytest (`smoke`, `regression` или маркер слоя UI) — это ОТБОР
тестов в прогон, allure-разметка — ГРУППИРОВКА в отчёте. Нужны оба:
модульный `pytestmark` обязателен по конвенции ([../tests.md](../tests.md)).

## Что попадает в отчёт автоматически

**Каждый HTTP-вызов — шаг Allure.** `HttpClient` оборачивает каждый
запрос в `allure.step("GET"/"POST"/...)` — в упавшем тесте видна
последовательность HTTP-методов до момента падения (шаг содержит только
метод, без URL). URL, тела запросов и ответов живут в файловом логе
`logs/log_*.log` ([failure-triage.md](failure-triage.md)) — отчёт
показывает «что происходило», лог — «что именно ушло и пришло».

<!-- слой: selenium -->
**Падение UI-теста → скриншот + page_source.** Хук
`pytest_runtest_makereport` в `Tests/Frontend_tests/conftest.py`
прикладывает PNG и HTML-исходник страницы в момент падения (в setup или
call).
<!-- /слой -->
<!-- слой: mobile -->
**Падение мобильного теста → скриншот + дерево элементов.** Хук
`pytest_runtest_makereport` в `Tests/Mobile_tests/conftest.py` прикладывает
скриншот экрана и XML-дерево элементов
(`DriverFunctions.attach_failure_diagnostics`). Разбор мобильного падения
начинай с этих вложений: видно и что было на экране, и какие
идентификаторы реально существовали.
<!-- /слой -->

Свои шаги в сложных сценариях добавляй тем же способом:

```python
with allure.step("Подготовка: создать проект с задачей"):
    ...
```

— но не оборачивай каждый ассерт: шаг полезен, когда группирует
осмысленный этап сценария.

## Как собрать и прочитать отчёт

```bash
make smoke        # или regression / mobile / frontend — результаты в testresults/
make report       # allure generate --single-file + открыть в браузере
```

`--single-file` — сознательный выбор шаблона: отчёт собирается в ОДИН
`allure-report/index.html`, который можно приложить к тикету, отправить
в чат или сохранить артефактом CI без веб-сервера и танцев с
`allure open`. Нужен установленный Allure CLI (а ему — Java).

В CI тот же путь: MR-смоук гоняет `./run_big_smoke_tests.sh` — он
запускает smoke, генерирует single-file отчёт и честно возвращает код
выхода pytest (пайп с `tee` его не маскирует). Ночной и regression-джобы
складывают `testresults/` артефактом, отчёт собирает стадия `report`
(см. [.gitlab-ci.yml](../../.gitlab-ci.yml) и «Ночной прогон» в
[../tests.md](../tests.md)).

Чтение упавшего прогона — сверху вниз: epic → feature → упавший тест →
description (что проверялось) → шаги (на каком вызове упало) →
вложения (скриншот/page_source) → и дальше в `logs/log_*.log` за телами
запросов. Если на любом из этих уровней «непонятно» — это дефект
разметки, чини его вместе с тестом.

## Частые ошибки

| Ошибка | Чем плоха |
|---|---|
| Тест без `@allure.feature` | падение висит в отчёте «нигде» — ищется дольше, чем чинится |
| description = имя теста («тест создания») | не помогает разбирающему; пиши проверку: «создание проекта возвращает id, поля сохраняются» |
| Разные feature для классов одного домена | домен расползается по отчёту |
| Ассерт-мясо без шагов в многошаговом сценарии | стектрейс есть, а на каком ЭТАПЕ упало — догадывайся |
| Разбор падения только по отчёту, без `logs/` | отчёт не содержит тел запросов — диагноз «на глаз» |
