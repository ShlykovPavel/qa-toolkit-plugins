# OpenAPI-спека для тестировщика: источник истины, а не справка

API-тест проверяет КОНТРАКТ — обещание сервиса, зафиксированное в
OpenAPI-спеке, — а не «как стенд отвечает сегодня». Пока эта разница не
прочувствована, тесты пишутся подгонкой под фактическое поведение и
теряют смысл: они зеленеют на любой регрессии, которая случилась до их
написания. Статья — как работать со спекой в этом шаблоне: что из неё
брать, чему не верить и зачем нужен срез.

---

## Что тест берёт из спеки

Для каждой операции ресурса:

- **путь и метод** — `POST /api/tasks`, а не «где-то так»;
- **тело запроса**: обязательные поля (`required`), типы, вложенность —
  отсюда негативные тесты «400 на пропущенное обязательное поле»;
- **коды ответов** — какие объявлены, такие и ассертим: create — 200 или
  201? delete несуществующего — 404 или идемпотентный 204?
- **схему ответа** — конверт списка (`{"data": [...], "total": ...}` или
  голый массив?), тип id (int или UUID?), формат ошибки;
- **какие операции ВООБЩЕ есть** — если у ресурса нет DELETE, фикстура
  с teardown-удалением — мёртвый код, а риск накопления тестовых данных
  на стенде — строка в отчёте.

## Главное правило: «как обычно» не бывает

Урок, оплаченный практикой: конвенции
РАЗЛИЧАЮТСЯ между ресурсами одного и того же API. Один ресурс отвечает
201 на create, соседний — 200; один отдаёт список конвертом, другой —
голым массивом; у одного id — int, у другого — UUID. Поэтому:

- коды и конверты для КАЖДОГО ресурса сверяются с его срезом спеки, а не
  берутся из соседнего домена или example-эталона;
- чего в спеке НЕТ — это **открытый вопрос** команде, а не догадка
  «типовое поведение». Список того, что нужно выяснить до кода, — Шаг 0
  в [../api-layer.md](../api-layer.md);
- «в примере кода стоит `response.get('data', response)`» — это защитная
  заглушка эталона, в реальном тесте её место занимает ассерт реальной
  структуры.

Спека молчит чаще, чем кажется: семантика фильтров списка, каскадность
delete, идемпотентность повторного создания, поведение при чужой роли —
этого в схемах обычно нет. Такие пункты фиксируются как вопросы (в
тестовой матрице или спеке домена) с пометкой, что принято допущением.

## Спека разошлась со стендом — что истина?

Запрос по спеке, ответ стабильный, но другой (код, конверт, поле) — это
диагноз «расхождение со спекой» из
[failure-triage.md](failure-triage.md). Не подгоняй ассерт: выясни у
команды, что истина. Варианта два, и оба — не про правку ассерта на
глаз: либо спека устарела (обновить её и спеку домена, потом тесты по
ней), либо стенд регрессировал (тикет + `xfail` со ссылкой). Тест,
молча подогнанный под стенд, узаконивает неизвестно что.

## Срез спеки: зачем и как

Полная спека реального проекта — мегабайты JSON: в контекст AI-агента не
влезает, а человеку в ней тонуть незачем. Рабочая единица — **срез**:
операции одного ресурса плюс только те схемы `components`, на которые
они транзитивно ссылаются через `$ref`. Делает его
`openapi_slice.py` (спека принимается и JSON, и YAML):

```bash
# что вообще есть в спеке: теги и число операций
openapi_slice.py --spec swagger.json --list-tags

# срез по тегу — в файл
openapi_slice.py --spec https://stand/openapi.json \
    --tag Contracts --out _specs/contracts.json

# нет тегов — срез по подстроке пути
openapi_slice.py --spec swagger.json --path /api/tasks --out slice.json
```

Срез удобен и без агентов: компактный JSON одного ресурса — готовая
шпаргалка для ручного тест-дизайна и код-ревью чужих тестов («а откуда
этот 204?» — открыл срез, проверил).

## Спека в конвейере скиллов

Путь к спеке — поле паспорта проекта (`docs/project-profile.md`,
заполняет `/setup-fork`). Дальше `/api-tests` и `/api-suite` режут срезы
сами и строят по ним тестовую матрицу; у каждой строки матрицы — источник
(`спека` / `паспорт` / `запрос` / `ДОПУЩЕНИЕ`), и слово «спека» там
означает «есть в срезе», а не «наверное так». Подробнее про процесс —
[ai-skills-guide.md](ai-skills-guide.md).

Нужен только срез, без тестов? Так и скажи агенту — «сделай срез по тегу
X и покажи» — это поддерживаемый режим `/api-tests`.

Спеки в проекте нет вовсе — контракт собирается вопросами (Шаг 0
[../api-layer.md](../api-layer.md)) и фиксируется в спеке домена; хуже,
дольше, но честно: каждый факт имеет источник, каждая дыра — пометку
«допущение».
