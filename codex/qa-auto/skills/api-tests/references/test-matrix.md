# Тестовая матрица API-ресурса (референс для Шага 2)

Минимум на CRUD-ресурс — расширенная версия матрицы из `docs/tests.md`.
Матрица показывается пользователю ДО кода в виде таблицы со столбцами:
**№ | Тест | Ожидаемый результат | Источник**, где источник —
`спека` / `паспорт` / `запрос` / `вики` / `ДОПУЩЕНИЕ` (`вики` — со страницей,
разделом или `TC-NN` и датой; правила строк из вики — Шаг 2 `SKILL.md`).

## Главное правило

**Коды ответов, конверты списков и формат ошибок — только из среза спеки,
паспорта или запроса пользователя.** Шаблонные example_* используют
«типовые» коды (create 200, delete 204) — это ОБРАЗЕЦ СТРУКТУРЫ, не истина
о реальном API. У одного проекта create может отдавать 201 для одного
ресурса и 200 для другого, список — конверт `{items, total}` у одного и
голый массив у другого. Не обобщай конвенцию одного ресурса на весь API;
чего в источниках нет — строка матрицы с пометкой ДОПУЩЕНИЕ.

**Второе правило: блок матрицы применяется, только если операция есть в
срезе.** У ресурса нет delete/update — не выдумывай их: вместо блока одна
строка «нет в спеке». Это касается и teardown-фикстур (см. Шаг 4 скилла).

## Блоки матрицы

| Блок | Тесты | Замечания |
|---|---|---|
| Create | happy path (создан, id возвращён); поля сохранились (create → get → сверка каждого переданного поля); **что легло в НЕпереданные поля** (см. Замечания); 400 на невалидные обязательные поля (пустая строка, null, нарушение minLength/maximum/enum из спеки); **граница длины/числа с ДВУХ сторон** (см. Замечания) | обязательность и ограничения — из requestBody среза. ВАЖНО: `deep_merge` не удаляет ключ при `None` — истинное ОТСУТСТВИЕ поля так не получить; тест на отсутствие пиши только если собираешь тело вручную, иначе строка «не покрывается через **kwargs». **Непереданные поля**: non-nullable тип без `required` в спеке молча получает default (`DateTime` → `0001-01-01`, int → `0`) и сохраняется с 200 — мусор в БД без ошибки, это баг API. **Граница с двух сторон**: ровно `maxLength`/`maximum` должно ПРОЙТИ, `+1` — дать 400; 500 на самой границе означает, что колонка БД уже объявленного лимита (`22001 value too long`) |
| Read | get по id — данные корректны; get несуществующего id — 404; список содержит созданный ресурс; конверт/пагинация списка соответствуют спеке (items/total/page или голый массив — как в срезе) | тип id смотри в спеке: integer и string-UUID требуют разных «несуществующих» значений |
| Update | PUT — изменение сохранилось: КАЖДОЕ изменяемое поле получает значение, отличное от прежнего, и в том же тесте update → get (или список) → сверка каждого поля; сверка только ответа PUT сохранение не проверяет — API может ответить новыми значениями и хранить прежние; PATCH — меняется ТОЛЬКО переданное поле, остальные нетронуты; update несуществующего — 404 | если в спеке только PUT или только PATCH — не выдумывай второй |
| Delete | delete → get возвращает 404; delete несуществующего — код из спеки, а если не документирован — ДОПУЩЕНИЕ (404 или идемпотентный 204 — подтвердить) | |
| Доступ | 401 без токена; 403 чужой ролью — для каждой операции, где спека/паспорт ограничивают роль | роли и ключи access_folder — из паспорта; не выдумывай имена ролей |
| БД | персистентность через `DbInfo.get_value_where` по таблицам, разрешённым в паспорте | только если паспорт даёт таблицы; нет доступа — строка «не покрывается, БД недоступна» |
| Не-CRUD | эндпоинты вне CRUD (отчёты, действия): happy path + 400 на невалидные обязательные query-параметры | по срезу |

## Примеры негативных вызовов

```python
Projects.get(999999999, status_code=404)          # несуществующий int id
Tasks.get("00000000-0000-0000-0000-000000000000", status_code=404)  # UUID id
Projects.create(name="", status_code=400)          # невалидное обязательное поле
Projects.create(name=None, status_code=400)        # null вместо значения (НЕ «отсутствие поля»: deep_merge ключ не удаляет)
Projects.get(project_id, access=None, status_code=401)           # без токена
Projects.delete(project_id, access="operator", status_code=403)  # чужая роль
```

Помни: при ожидаемой ошибке (status_code >= 400) клиент возвращает `None` —
результат негативного вызова НЕ разыменовывать.

## Чего в матрице быть НЕ должно

- Тестов, читающих данные другого теста (независимость — железное правило
  `docs/tests.md`).
- Фиксированных имён/email — только генераторы `src/data_generators.py`.
- `time.sleep` — асинхронность ждать через `wait_until()`. После мутации с
  побочным эффектом на связанный ресурс (`order`, `hide`, `show` и
  подобные) результат тоже проверяется `wait_until`, а не одиночным GET:
  чтение сразу после мутации на живом стенде иногда видит старое значение.
  Условие ожидания — **равенство целевому** (`return v if v == target else
  None`), а не «значение появилось»: старое значение тоже truthy, и
  несработавшее действие выглядит как гонка.
- Сравнения отметок времени из API строками — стенд отдаёт дробную часть
  переменной длины, и лексикографический порядок не равен временному;
  перед сравнением `datetime.fromisoformat`.
- Ассертов списка по количеству там, где стенд общий и данные копятся, —
  проверяй принадлежность созданного.
- Тестов «на всякий случай» вне запрошенного ресурса — скоуп определяет
  запрос, а не фантазия.
