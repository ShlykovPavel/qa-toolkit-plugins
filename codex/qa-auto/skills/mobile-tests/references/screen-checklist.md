# Чеклист слоя экрана (референс для Шага 5)

Три файла на фичу — строго по эталонам (копия эталона, не расширение):
`Appium/app_keys/example_feature_buttons.py`,
`Appium/Modules/example_module.py`,
`Tests/Mobile_tests/test_mobile_example.py`. Семантика слоя — docs/mobile.md.

## app_keys/<фича>_buttons.py — ТОЛЬКО локаторы

- [ ] Класс `<Фича>Buttons(ScreenActions)` — наследовать **ScreenActions**,
      НЕ BaseElements (BaseElements — готовый набор общих элементов для
      модулей, не база для наследования).
- [ ] Статичный элемент → `@property`, возвращающий `self.get_element("<id>")`.
- [ ] Динамический элемент (id сущности из API) → метод с параметром:
      `def item_tile(self, item_id: str): return self.get_element(f"app_..._{item_id}")`.
      id сущности — строка (uuid), не индекс позиции.
- [ ] Идентификатор в `get_element` — «голый», как в контракте
      (`app_login_submit_button`), БЕЗ `<package>:id/` — обвязку слой
      добавляет сам.
- [ ] Каждый идентификатор существует в дампе или помечен ДОПУЩЕНИЕМ в
      матрице. Никакой логики, ожиданий, ассертов — только локаторы.

## Modules/<фича>_module.py — взаимодействия

- [ ] Класс `<Фича>Module`: `__init__(self, driver)` создаёт
      `self.buttons = <Фича>Buttons(driver)` и `self.base = BaseElements(driver)`.
- [ ] **`Logger.log_mobile_action(...)` — ПЕРВОЙ строкой КАЖДОГО метода
      действия** (главный источник диагностики: мобильный цикл медленный).
- [ ] Модуль знает «как сделать» (open/create/fill через click_element /
      type_text / scroll_until_visible), тест знает «что проверить» —
      ассерты в тестах.
- [ ] Есть steps.json из walkthrough → шаги сценария ложатся в методы
      модуля почти один в один.

## Tests/Mobile_tests/test_<фича>.py — сценарии и ассерты

- [ ] `pytestmark = pytest.mark.mobile`, `@allure.epic("Mobile")`,
      `@allure.feature(...)`, класс `Test<Фича>`.
- [ ] Драйвер — инфраструктурной фикстурой `driver` (autouse, уже в
      conftest) — НЕ создавать свой. Логин — фикстурой форка
      (`login_in_app`-образец в conftest), не в теле теста.
- [ ] Предусловия данных — API-клиентами `src/` в фикстурах домена
      (create → yield id → delete), НЕ через UI. Нет клиента — сначала
      `qa-auto:api-clients` (Шаг 5 SKILL.md; UI-обход не городить).
- [ ] Уникальные данные — `src/data_generators.py`; ожидание асинхронщины —
      `wait_until`, не `time.sleep`. Переход, различимый только по
      промежуточному состоянию (PIN «Придумайте» / «Повторите» — один виджет,
      отличающего идентификатора нет), гоняется циклом `wait_until`: условие —
      появление СЛЕДУЮЩЕГО якоря с идентификатором, действие повторяется каждую
      итерацию. Нет идентификатора на контейнере экрана — заявка в `/keys-mobile`.
- [ ] Проверка ОТСУТСТВИЯ элемента — `is_element_not_presented("<id>")`.
      `element_expected=False` — это ассерт отсутствия, элемент НЕ
      возвращает никогда; «достать элемент, если есть» им нельзя.
- [ ] Проверка текста — `assert_text(element, "<ключ локализации>")`;
      строки НЕ хардкодить (ломаются локалью). Поиска по тексту в слое нет.
- [ ] Каждая строка матрицы Шага 4 → шаг теста (или пометка в отчёте).
- [ ] Шаги, которые тест проверяет, — в теле теста (или в Module, вызванном
      из тела), не в conftest-фикстуре: там только предусловия и teardown.
- [ ] Созданное регистрируется в cleaner сразу после создания, до шагов,
      способных упасть.
- [ ] Тест доводит приложение до состояния, переживающего перезапуск (вход,
      PIN, сессия) → запрошена фикстура `reset_app_after_test` из
      `Tests/Mobile_tests/conftest.py` (iOS — переустановка, Android —
      `mobile: clearApp`). Свою копию такого сброса в conftest фичи не
      писать (`.claude/rules/mobile.md`, «Состояние приложения между
      тестами»).
- [ ] Тесты независимы: без порядка, без общих словарей, параллелизуемы.

## Самопроверка перед `make verify`

- [ ] Чеклист пройден по ГОТОВОМУ коду, а не только прочитан на входе.
      Логика, перенесённая из отладочных скриптов прохода, переписана под
      конвенции (паузы оттуда — первое, что утекает в модуль).
- [ ] В коде нет XPath, координат, текстовых локаторов.
- [ ] В коде нет секретов и URL — только env-имена из паспорта.
- [ ] example_*-файлы не изменены (копировались, не редактировались).
