# Фазовый оркестратор покрытия (test-flow)

Вход — фича/тикет/домен, который нужно покрыть тестами на нескольких
слоях или «по полному циклу». Ты — ОРКЕСТРАТОР: ведёшь фазы
D (обсуждение) → P (план) → E (выполнение) → R (ревью) → S (итоги),
**сам тесты не пишешь** — код создают сабагенты. Какие слои покрывать —
решает ТЕСТЕР в фазе D, не паспорт: паспорт лишь говорит, что настроено.
Работаешь в ГЛАВНОЙ сессии (нужен Agent tool — целиком сабагенту флоу
не делегировать: сабагент не спавнит сабагентов, фазы молча деградируют).

## Шаг 0 — Pre-flight (первым действием, до любой другой работы)

| Ситуация | Действие |
|---|---|
| Паспорта `docs/project-profile.md` нет | Одной фразой: «форк не настроен, запусти /setup-fork» — и СТОП. |
| Запрос про ОДИН слой (в т.ч. сквозной API-сценарий/флоу из нескольких эндпоинтов или доменов — это всё ещё ОДИН слой, порога не создаёт): ресурс/эндпоинт/флоу API → /api-tests; страница/Selenium/Playwright → /frontend-tests; экран/Appium/мобилка → /mobile-tests | Одной фразой отошли к слоевому скиллу и верни управление. |
| «Покрой весь API / все ресурсы спеки» | Одной фразой отошли к /api-suite. |
| Ревью СУЩЕСТВУЮЩИХ тестов без нового покрытия | Одной фразой отошли к /review-tests. |
| Починка/отладка падающих тестов | Одной фразой: вне скоупа флоу; верни управление. |
| Запрос «продолжи <slug>» ИЛИ в `docs/coverage/*/log.md` есть незавершённая фаза | Режим **RESUME** (секция ниже). Slug не назван → перечисли `docs/coverage/*/` и уточни, с какого продолжать. |
| Иначе | Прочитай паспорт целиком. Заведи артефакты флоу и task-лист (секция ниже). Фаза D. |

**Оснащение машины — прогоном, а не памятью.** В этом же шаге:

```bash
preflight.py --use-marker
```

Молчит, пока на машине ничего не менялось (маркер `.preflight-ok` привязан к
хосту, не к клону — репозиторий ездит между машинами). Красное **не чинишь и
ничего не ставишь**: называешь пользователю, какой класс работы закрыт (колонка
«без неё» в выводе прогона), и продолжаешь в оставшемся
объёме — недостача идёт в отчёт. Для этого скилла критичны: всё, что задействуют запланированные фазы, — прогон делается ОДИН раз здесь, до раздачи работы агентам, а не каждым агентом заново.

**Автономный режим** = пользователь недоступен или явно попросил без
вопросов: каждый гейт фиксируется в log.md строкой «гейт пройден
допущением» вместо ожидания подтверждения; все допущения — в отчёт
фазы S.

## Артефакты, log.md и task-лист (инфраструктура флоу)

`docs/coverage/<slug>/` (slug — короткое имя задачи): `spec.md` (фаза D),
`plan.md` (фаза P), `log.md` — ЖУРНАЛ И ИСТОЧНИК ПРАВДЫ. Обязательные
поля log.md: текущая фаза и статус её гейта (ждёт / пройден / допущение);
счётчик кругов R; **список созданных флоу файлов** (граница «только
своё»); спавненные агенты со статусами (запущен / завершён / оборван);
допущения; следующий конкретный шаг. Обновляй log.md В МОМЕНТЫ РИСКА,
не в конце фазы: перед КАЖДЫМ спавном агента, после финиша каждого
агента, на каждом гейте — обрыв сессии не должен терять прогресс.

**Task-лист (видимость для человека):** на старте создай задачи-фазы
(D/P/E/R/S) через TaskCreate; вход в фазу → in_progress (activeForm —
что конкретно происходит), гейт пройден → completed. В фазе E — ПО
ЗАДАЧЕ НА КАЖДОГО агента («writer: домен contracts»), создаётся перед
спавном, закрывается по финишу — человек видит текущего сабагента во
время фоновой работы. Откат R→(E|P) = НОВАЯ задача круга («круг 2:
починка находок R»). Task-лист не переживает сессию — статусы дублируй
в log.md. Task-инструментов нет в сессии → веди только log.md, это не
нарушение.

**Граница «только своё»:** флоу создаёт и правит ТОЛЬКО файлы из списка
созданных в log.md (+ сами артефакты docs/coverage/). Существующие тесты,
`src/auth.py`, `Tests/conftest.py`, `example_*`, `docs/*.md` — не трогать;
находки/потребности по чужому — отчётом.

## Фаза D — Обсуждение → spec.md

Из тикета/описания и вопросов тестеру собери: ЧТО покрываем, КАКИМИ
СЛОЯМИ (его выбор; предложи варианты из настроенных в паспорте, но не
навязывай), где источники (срез спеки / страницы / экраны), что
считается «готово». Вопросы — ПАЧКОЙ, не по одному. `spec.md`: скоуп,
слои, источники, критерии готовности, риски, открытые вопросы таблицей.
Спека может содержать НЕСКОЛЬКО независимых срезов «слой × сущность»
(API Contracts + UI Users — легально). **ГЕЙТ: покажи spec.md сводкой и
дождись подтверждения.**

## Фаза P — План → plan.md

По spec.md: порядок работ, способ делегации каждого среза, что
параллелится, план ревью. Матрицы: для API-срезов спеку домена готовит
агент `test-spec-writer` (спавн в этой фазе, его вопросы — тестеру; отчёт
со `СПЕКА НЕ ЗАПИСАНА: <путь>` — запиши текст спеки из отчёта сам);
для НЕ-API срезов (фронт, мобилка) детальную матрицу НЕ порождай и не
импровизируй — её построит слоевая процедура в фазе E (их конвенция
«матрица ДО кода» сохраняет дисциплину; зафиксируй это в plan.md).

**Сбор «глаз» — ТВОЯ обязанность, здесь, ДО спавна кого-либо.**
Сабагент НЕ может вести диалог с человеком (его вопросы умирают), а
walkthrough исполняется руками тестера — поэтому по каждому срезу
определи источник локаторов по развилке Шага 2 слоевого скилла и закрой
его СЕЙЧАС:

| Источник среза | Что делаешь |
|---|---|
| Страница/экран достижимы без человека (URL/file без логина) или дампы уже отданы | Пометка в plan.md «сабагент снимет сам» / пути готовых дампов |
| Нужен человек: за логином, состояния без URL, живое устройство | Выдай тестеру рецепты ПРЯМО В ОТВЕТ (walkthrough и др. — секции «для человека» docs/frontend.md / docs/mobile.md), ДОЖДИСЬ артефактов, проверь их (папка на месте, steps.json читается) и зафиксируй ПУТИ в plan.md |
| Playwright/Appium MCP подключён к ТВОЕЙ сессии | Можешь снять сам в этой фазе (диалог «шаг — снимок» с тестером), снапшоты сохрани в файлы, пути — в plan.md |
| Автономный режим / показать нечем | Срез помечается «по допущениям» в spec.md и отчёте |

Гейт P не проходится, пока источник каждого среза не закрыт (или явно
«автономно»). **ГЕЙТ: покажи plan.md сводкой и дождись подтверждения.**

## Фаза E — Выполнение (делегация; сам код НЕ пишешь)

Строго по plan.md:

- **API-срез** → агенты-роли плагина: writer — `qa-auto:test-writer` с
  вводными среза; после — fixer `qa-auto:test-fixer` до зелёного verify.
- **Срез без агент-роли (фронт, мобилка)** → один сабагент `general-purpose`
  на срез с промптом «вызови скилл `qa-auto:<frontend-tests|mobile-tests>` и
  действуй по нему» + вводные (его процедура построит матрицу, напишет код и прогонит
  verify).

**Вводные сабагента закрывают ВСЕ развилки его процедуры** — он не может
спросить ни человека, ни тебя: передай пути к артефактам-«глазам» из
plan.md явно («дампы сценария в <путь>, живые страницы НЕ снимать» —
либо «страница доступна по <URL>, сними дамп сам»), ветку выбора
способа съёмки в его Шаге 2 объяви уже решённой. Сабагент упёрся в
недостающий артефакт → это ВОЗВРАТ В ФАЗУ P (собрать с тестером и
переспавнить), а не повод сабагенту импровизировать.

Перед каждым спавном — запись в log.md и задача в task-листе; после
финиша — статус агента, список созданных им файлов в log.md,
`make verify`. Агент оборвался — зафиксируй «оборван», полуфабрикат
чинит fixer до продолжения. **ГЕЙТ-сводка: что создано, verify-статус,
допущения агентов КОПИЕЙ.**

## Фаза R — Ревью (агент, не скилл)

Спавни агента `qa-auto:test-reviewer` со скоупом =
список созданных файлов из log.md (скилл /review-tests НЕ вызывай —
чеклист у агента тот же). Находки классифицируй и реши ОТКАТ: баг кода →
точечно назад в E (fixer по находкам); кривая матрица/спека среза →
назад в P; непонимание скоупа → в D, только через пользователя. Лимит
2 круга R→(E|P), счётчик кругов — в log.md и отчёт (0 кругов — тоже
значение). Находки по чужим файлам — «вне скоупа» отчётом, не править.
**ГЕЙТ: сводка находок и решений.**

## Фаза S — Итоги

Сводный отчёт: покрытие ПРОТИВ spec.md (срез → сделано / xfail / требует
человека); созданные файлы; verify-статус; допущения и открытые вопросы —
КОПИЕЙ из spec/plan/отчётов агентов («допущений нет» — явной строкой);
техдолг и что попросить у разработчиков; счётчик кругов R. Найденная в флоу ловушка
ПРОЕКТА (нестабильный селектор, особенность стенда, флаки, расхождение
доки с фактом — в т.ч. из отчётов сабагентов) → допиши её коротко в
секцию «Копилка ловушек проекта» соответствующего `docs/*.md` или в
паспорт И упомяни в отчёте.

**Для вики.** Что флоу выяснил о продукте — правило, которого в вики нет,
расхождение стенда с вики, баг стенда, вопрос продукту (в т.ч. из отчётов
сабагентов и открытых вопросов spec.md) — блоком «Для вики» в сводном
отчёте: находка → эндпоинт или экран → где она записана в автотестах.
Блок — не вопрос: дальше сразу раскладка по страницам вики тестеру (куда
что ложится — справочник «находка стенда» скилла `qa:kb-ingest`). Вопрос
один, на раскладке. После «да» первым действием **вызови скилл
`qa:kb-ingest`** с находками и пометкой «раскладка показана, „да“
получено» — вики пишет он; сам по справочнику вики не правь. Паспорт и `docs/*.md` остаются —
вики они не заменяют. Автономный режим или «нет» — блок остаётся в отчёте с
пометкой «не занесено». Находок нет — строка «для вики: нет». Вики у
проекта нет (`qa-paths wiki` отвечает ошибкой) — блока нет.

log.md: фаза S, флоу завершён.

## RESUME (восстановление после обрыва)

1. Прочитай `docs/coverage/<slug>/`: spec.md, plan.md, log.md.
2. СВЕРЬ журнал с диском: созданные файлы на месте? `make verify`
   зелёный? Агенты со статусом «запущен» — их файлы целы или
   полуфабрикат? Расхождения — в log.md; полуфабрикаты чинит fixer
   ПЕРЕД продолжением.
3. Пересоздай task-лист по log.md (завершённые фазы — completed).
4. Покажи сводку «где мы» и продолжи с ТЕКУЩЕЙ фазы от её гейта:
   пройденные гейты не переспрашивай, spec/plan без явной просьбы не
   пересоздавай, флоу заново не начинай.

## Границы и безопасность

- Сам тесты/клиенты/локаторы НЕ пишешь — только сабагенты (фаза E).
- «Только своё»: чужие файлы не правишь (список — в log.md).
- Слоевые скиллы и их конвенции — источник процедур срезов; их файлы
  и `example_*` не изменяй.
- Никаких секретов и хардкода URL — только `config.py`/`.env`.
- Не коммить без явной просьбы.
