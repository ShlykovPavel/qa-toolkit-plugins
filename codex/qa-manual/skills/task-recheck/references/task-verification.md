# Скилл `task-recheck` — перепроверка задачи

> Открывай, **когда предстоит перепроверка задачи или бага**: что скилл делает, где его
> стоп-гейт, как подключается скептик и как считается стоимость захода. Сам скилл — `SKILL.md` рядом,
> его вызов эти правила не заменяют.

Процедура перепроверки задачи — скилл **`task-recheck`** плагина `qa-manual`. Он универсальный: специфика проекта вся живёт в
`project-passport.md`, скилл про конкретные стенды и инструменты не знает.

Что внутри: флоу фаз 0–6, два режима (перепроверка задачи и малый заход на один баг),
четыре корзины классификации критериев, формат кейсов и отчёта, восемь классов претензий
скептика, `${PLUGIN_ROOT}/bin/spec-diff.py` (снапшот ↔ живая спека) и `${PLUGIN_ROOT}/bin/evidence.py` (сырьё прогона, объём
выборки, мутационная проба, строка стоимости захода).

**Отдаёт результат покрытием, а не вердиктом:** «критерий → покрыт → чем именно». Вердикт
«задача сделана» остаётся человеку.

**Фронтовые кейсы уходят в `ui-bug-sweep`** — он раннер фронта, свои критерии «баг / не
баг» для фронта скилл не изобретает.

**Стоп-гейт фазы 0 — не формальность.** Не заполнены обязательные поля паспорта (разделы 1 и 8,
три строки раздела 2), нет доступной базы знаний, нет доступа к дословным критериям — работа не
начинается, агент перечисляет, чего не хватает. Догадка вместо факта запрещена: не нашёл сам —
это вопрос человеку, а не гипотеза.

**Незаполненное вне обязательных полей гейт не держит, а размечает.** Пустое поле читается как
«возможности нет»: кейсы этого класса уходят на человека, и в отчёте появляется строка «класс
проверок закрыт, потому что в паспорте не объявлен доступ к X». Так вход в новый проект не
упирается в опрос из сорока полей, а пропущенный класс проверок остаётся видимым.

**Скептик — отдельный субагент** `skeptic-evidence`, только чтение. Подключается трижды:
`скептик-по-кейсам` до прогона, `скептик-по-выводам` вместе с сырьём прогона до отчёта и
`приёмка-починок` после того, как претензии отработаны — последний проводит агент, правок не
ставивший. Претензия без цитаты не считается, «претензий нет» — легитимный результат.

**Отчёт — один файл: шапка и разбор под чертой.** Сверху пять-семь строк, из которых видно,
надо ли читать дальше: вердикт по дефекту с пятью полями, дробь покрытия, что осталось
непокрытым, список находок ссылками. Ниже черты — разбор по десяти разделам, он пишется
всегда и не сокращается. Баг-репорты живут отдельным документом и уезжают в трекер через
`tracker-filing`.

**Последняя строка раздела «Метод» — стоимость захода.** Считается только то, что агент
наблюдает своими глазами: вызовы субагентов по ролям, прогоны раннера и запросы, файлы сырья,
заходы скептика с числом принятых претензий, вмешательства человека. Машинную часть печатает
`${PLUGIN_ROOT}/bin/evidence.py cost`, остальное агент ведёт по ходу захода. Токенов и длительности в строке нет
намеренно — их агент не наблюдает и потому не измерит, а оценит; величина без подтверждения
пишется как «не считалось».

**Заход ведёт субагент, а ты оркестрируешь** — `references/orchestrator-playbook.md` в скилле:
роли, нарезка заданий по фазам (задание кончается там, где начинается апрув), кто пишет файлы
фазы 6, кто собирает вход скептику и четыре вопроса к возвращённому пакету.


**Приёмочный корпус скептика** (опционально) — набор данных с известным правильным
ответом для замера полноты скептика: данные отдельно, ключ с ответами отдельно
(намеренно — агент, увидевший ключ, обесценивает замер). Заводится по мере необходимости
на конкретном проекте, шаблона в этом репозитории нет.
